# chr-container-rose

Готовые образы RouterOS CHR (x86_64, raw) с включёнными контейнерами — для
записи на диск VPS через `dd` или для импорта в гипервизор.

## Что внутри образа

- стоковый CHR указанной версии с официальными пакетами `container` и
  `rose-storage`;
- `device-mode` в режиме `advanced` с `container=yes` и `traffic-gen=yes` —
  то, что обычно требует физического подтверждения, уже подтверждено;
- пустая конфигурация: сброс `no-defaults=yes skip-backup=yes` выполнен без
  подключённой сетевой карты, поэтому первая сетевуха машины, на которую
  записан образ, встаёт как `ether1`;
- лицензия `free`, пользователь `admin` в заводском состоянии, никаких
  следов сборки.

На пустой конфигурации CHR сам поднимает DHCP-клиент на `ether1` — это
встроенное поведение RouterOS, не часть сборки.

## Где взять

В [Releases](../../releases): образ `chr-<версия>-container-rose.img` и его
`.sha256`. Контрольная сумма продублирована в описании релиза.

## Как собирается

Весь процесс идёт без ввода в консоль: последовательная консоль CHR на любой
ввод перерисовывает экран логина, поэтому RouterOS управляется скриптами,
заранее записанными в раздел образа.

1. В стоковый образ записываются `rw/autorun.scr` и `rw/disk/build-stage2.rsc`.
   При первой загрузке `autorun` скачивает оба пакета с локального HTTP-сервера
   сборщика и чисто перезагружается — при загрузке пакеты устанавливаются.
2. Вторая часть проверяет пакеты, планирует сброс конфигурации на следующий
   старт и запрашивает `device-mode`. Сборщик обрывает питание ВМ — это и есть
   подтверждение.
3. Образ загружается без сетевой карты, запланированный сброс стирает
   конфигурацию и перезагружает RouterOS.
4. После чистой загрузки ВМ выключается через ACPI без входа в систему, а в
   `rw/store` возвращается стоковый пустой `autorun.scr`.
5. Одноразовая копия образа загружается с проверочным скриптом, который
   выгружает состояние в файлы; сборка падает, если хоть что-то не сходится.

О ходе выполнения гость сообщает HTTP-запросами к сборщику, так что файлов-меток
в образе не остаётся. Код — в [`builder/`](builder/).

## Собрать через GitHub Actions

Actions → **Build CHR image** → Run workflow:

| Параметр | Назначение |
| --- | --- |
| `version` | версия RouterOS, например `7.24.4` |
| `publish` | опубликовать релиз; иначе образ будет артефактом запуска |
| `latest` | пометить релиз как Latest |
| `long_term` | подписать релиз как long-term |
| `accel` | `kvm` (по умолчанию) или медленный запасной `tcg` |

Существующий релиз workflow не перезаписывает. Логи сборки и результаты
проверки сохраняются артефактом запуска в любом случае.

## Собрать локально

```
python builder/build.py 7.24.4
```

Результат — в `<CHR_BUILD_ROOT>/out/`.

- **Linux**: `qemu-system-x86`, `unzip`, `sfdisk`, `sudo` (для loop-mount).
  Если `/dev/kvm` доступен, используется KVM. `CHR_BUILD_ROOT` по умолчанию —
  `work/` в корне репозитория.
- **Windows**: QEMU (путь задаётся переменной `QEMU`), 7-Zip и запущенный
  Docker Desktop — через него монтируется раздел образа. QEMU работает в
  эмуляции TCG: под аппаратным ускорением Hyper-V процессы RouterOS падают.
  `CHR_BUILD_ROOT` по умолчанию — `D:\chr-build`.

## Оговорка

RouterOS — продукт MikroTik, проект с MikroTik не связан. Образы собираются из
официальных загрузок `download.mikrotik.com`: программное обеспечение не
изменяется, выполняется только установка официальных пакетов и настройка
`device-mode` штатными средствами RouterOS.
